# calculator-interview

> 招新考核训练场：一个只会加法的计算器网页，`js/main.js` 里只留了一个空的 `add()`。这里是组织里**唯一对外部候选人开放**的仓库，所以这里的规矩＝[guidelines](https://github.com/GXMZU-AITECC/guidelines)＋本页这一小段增补。

## 靠它进社团

不用打招呼：fork、提 Issue、提 PR。流程、红线、处分全在 guidelines 里，本页只写这个仓特殊的地方。通过标准只有一条——**PR 被合并**。入社之后不用再回来，内部协作走各项目仓库。

## 题目自己出

你觉得这个计算器还缺什么，就提什么功能提案；写法看 Issues 里标题带「示范」的那条；认领方式是在自己的提案 Issue 下回一句「认领：姓名＋fork 链接＋分支名」，7 天内不提 PR 占题作废。**没灵感就去抄现成的**：手机自带计算器、Windows 计算器、任意一个网页计算器，随便挑一个功能照做，照抄不扣分。范围不出这个网页：要装依赖、要引框架、要换语言的提案一律拒。

## 打回怎么写（人话版）

审核人打回**只写编号**，不写长篇大论。分两层看：

1. **通用红线（T / P）**：只看 [guidelines](https://github.com/GXMZU-AITECC/guidelines)，例如 `违反 T8`、`T0、T6`。
2. **本仓额外要求（CT）**：只看下面这张表，例如 `违反 CT2`。

能归到 T 的优先写 T；只有本仓额外要求才写 CT。对编号有异议，在 PR 里追问即可。

### CT · 本仓增补打回条例

| 编号 | 啥情况打回 |
| :--- | :--- |
| **CT0** | 没用原生单文件 JS：装包、引 CDN、加构建工具、把逻辑拆出 `js/main.js`；Issue 里也没拿到 `reviewers` 批准 |
| **CT1** | 动了显示区 DOM 结构，或改了 `js/main.js` 里已有函数签名 |
| **CT2** | PR 里没有浏览器实际效果截图 |
| **CT3** | 功能提案明显超出「这一个计算器网页」（要换语言、上框架、搞后端等），且 Issue 未获批 |
| **CT4** | 提完 PR 后删了自己的 fork，或乱改 fork 默认分支，导致 PR 失效/无法继续审 |

> CT 只管本仓增补。代码好不好看、注释全不全、提交信息美不美——**都不构成打回依据**（和 guidelines 口径一致）。

## 本仓增补（规范之外，只在这里生效）

| 增补 | 内容 | 对应 CT |
| :--- | :--- | :--- |
| **只用原生 JS** | 不装包、不引 CDN、不加构建工具，逻辑写在 `js/main.js` 一个文件里不拆分层；确实绕不过（比如安全的表达式解析），先在 Issue 里写清理由，`reviewers` 批了才能用 | CT0 |
| **骨架只锁两样** | 显示区的 DOM 结构、`js/main.js` 里已有的函数签名——不动。样式随你改（`css/style.css` 可新增可重写，黑白模式、换肤、动画都行），显示区之外要加按钮也可以 | CT1 |
| **验收要图** | PR 里附一张浏览器实际效果截图，没图不算做完 | CT2 |
| **公开仓，内部资产** | 本仓对外可见，但题目、代码、Issue 与 PR 讨论——包括你的 fork 和答题截图——都按社团内部资产对待，不得挂进公开简历、博客、社交账号（**P0**） | 走 guidelines **P0** |
| **评审不用你操心** | 外部账号没有 assign 权限：提完 PR 等就行。本仓用 CODEOWNERS 把评审自动派给 `reviewers` team，谁认领谁评审，第二名认领的 Reviewer 批准并合并（T5）。**提完 PR 别删你的 fork、也别改 fork 的默认分支**，否则 PR 会失效 | CT4；评审流程走 **T5** |
